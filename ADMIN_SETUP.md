# Админка «Чевапно Место» — установка на Рег.ру (Host-A)

Админка — это папка `admin/` на чистом PHP, без базы данных и без сборки.
Данные лежат в JSON-файлах в `data/`. При каждом сохранении админка сама
пересобирает `js/content.js`, поэтому главная страница и её анимации
работают как раньше, без задержек. `menu.html` читает `data/prosek.json` напрямую.

Сайт работает и без PHP (как на GitHub Pages) — просто без админки.

---

## 1. Что нужно на хостинге

- **PHP 8.1 или новее.** ISPmanager → «Сайты» → выберите сайт → «Изменить» → «Версия PHP» → 8.2 или 8.3.
- **Расширения PHP:** `gd` (обработка фото), `mbstring`, `fileinfo`, `exif` (поворот фото с телефона).
  На Host-A они обычно включены. Проверка — в разделе 6.
- **Лимиты загрузки:** ISPmanager → «Сайты» → сайт → «Изменить» → «Настройки PHP»:
  - `upload_max_filesize` = 12M
  - `post_max_size` = 14M
  - `memory_limit` = 256M (для больших фото с телефона)

  Если поменять лимиты нельзя, ничего страшного: админка сама уменьшает большие фото ещё в браузере перед загрузкой.

## 2. Какие файлы загрузить по FTP

Папка сайта в ISPmanager обычно `/var/www/u1234567/data/www/ваш-домен.ru/`
(раздел «Менеджер файлов» или FTP-клиент, например FileZilla).

Загрузить:

```
index.html
menu.html
.htaccess
css/
js/
assets/            (вместе с assets/img/uploads/ и её .htaccess)
data/              (вместе с data/_backups/ и её .htaccess, но без файлов *.json внутри _backups)
admin/             (БЕЗ admin/config.php — его создадим на сервере, раздел 4)
```

Не загружать: `tools/`, `.github/`, `.git/`, `README.md`, `ADMIN_*.md`.

> Скрытые файлы `.htaccess` FileZilla по умолчанию показывает. Если вашего
> клиента не видно — включите «Показывать скрытые файлы». Без `.htaccess`
> резервные копии и служебные файлы будут открыты наружу.

## 3. Права на запись

PHP на Рег.ру работает от имени вашего пользователя, поэтому хватает стандартных прав:

| Что | Права | Зачем |
|---|---|---|
| `data/` | 755 | PHP пишет сюда JSON (через временный файл) |
| `data/*.json` | 644 | |
| `data/_backups/` | 755 | резервные копии и журнал попыток входа |
| `js/` | 755 | PHP пересобирает `js/content.js` |
| `js/content.js` | 644 | |
| `assets/img/uploads/` | 755 | загруженные фото |
| `admin/config.php` | 640 | хэш пароля |

Если при сохранении админка пишет «Нет прав на запись…», значит PHP запущен
от другого пользователя — тогда поставьте этим папкам 775, а файлам 664.

## 4. Пароль

**Вариант А — через SSH** (на Host-A SSH включается в ISPmanager → «Пользователи» → «Изменить» → «Доступ к shell»):

```bash
cd ~/www/ваш-домен.ru
php admin/tools/set-password.php "Длинный-пароль-для-кафе"
```

Скрипт создаст `admin/config.php` с хэшем. Сам пароль нигде не хранится.
Сменить пароль — запустить ту же команду с новым.

**Вариант Б — без SSH.** На своём компьютере, где есть PHP:

```bash
php -r "echo password_hash('Длинный-пароль-для-кафе', PASSWORD_DEFAULT), PHP_EOL;"
```

Скопируйте `admin/config.example.php` в `admin/config.php` и вставьте
получившуюся строку (начинается с `$2y$`) в `'password_hash' => '...'`.
Загрузите `config.php` по FTP в `admin/`.

Пароль — не короче 10–12 символов. После пяти неверных попыток вход с этого адреса
закрывается на 15 минут.

## 5. Резервные копии — лучше вне папки сайта

Перед каждым сохранением админка кладёт копию раздела в `data/_backups/`
(последние 30 копий каждого раздела). Папка закрыта через `.htaccess`.

На части хостингов статические файлы отдаёт nginx, и `.htaccess` на них не
действует. После первого сохранения проверьте в браузере:

```
https://ваш-домен.ru/data/_backups/
```

и ссылку на любой файл копии из этой папки (имя видно в менеджере файлов).
Должна быть ошибка 403/404. Если файл открывается — перенесите копии из папки сайта:

1. Создайте папку рядом с `www`, например `/var/www/u1234567/data/chevapno-private`.
2. В `admin/config.php` укажите: `'store_dir' => '/var/www/u1234567/data/chevapno-private',`

Ничего секретного в копиях нет (это меню, которое и так на сайте), но лучше закрыть.

## 6. Проверка, что всё работает

**Поддержка WebP в GD.** Через SSH:

```bash
php -r 'var_dump(gd_info()["WebP Support"] ?? false, function_exists("exif_read_data"));'
```

Без SSH: создайте файл `check.php` с текстом `<?php var_dump(gd_info());`,
откройте его в браузере и **сразу удалите**. Если WebP не поддерживается,
админка сама будет сохранять фото в JPEG — это тоже нормально.

**Дальше по шагам:**

1. Откройте `https://ваш-домен.ru/admin/` — должна быть страница входа.
2. Войдите, поменяйте цену любого блюда, нажмите «Сохранить» → «Сохранено, изменения уже на сайте».
3. Откройте сайт в новой вкладке — цена новая.
4. Раздел «История» — появилась копия; «Восстановить» вернёт старую цену.

## 7. Что где лежит

```
admin/index.php         интерфейс (после входа)
admin/login.php         вход и выход
admin/api.php           сохранение, загрузка фото, история
admin/lib/              хранилище, проверка данных, сборка content.js, фото, вход
admin/assets/           стили и скрипт интерфейса
admin/config.php        хэш пароля и настройки (создаётся на сервере, в git не попадает)
admin/tools/set-password.php    пароль из консоли
admin/tools/build-content.php   пересобрать js/content.js из data/*.json

data/main.json          меню главной, витрина, бегущие строки
data/prosek.json        меню 5-й Просеки (его читает menu.html)
data/lunch.json         ланчи
data/points.json        точки, часы, телефоны, соцсети, условия доставки (правится вручную)
data/zone.json          зона доставки на карте (правится вручную)
data/_backups/          резервные копии
assets/img/uploads/     фото, загруженные через админку
js/content.js           ГЕНЕРИРУЕТСЯ — вручную не править
```

### Правка точек, часов и доставки (вручную)

Клиент меняет это редко и просит вас. Откройте `data/points.json`, поправьте
адрес, часы или телефон и пересоберите главную:

```bash
php admin/tools/build-content.php
```

(или просто нажмите «Сохранить» в любом разделе админки — `content.js`
пересоберётся вместе со всеми данными). Если меняются телефон или часы
5-й Просеки, поправьте их ещё в `data/prosek.json` (блок `place`) и в
`data/zone.json` (блок `store`).

### GitHub Pages

Workflow публикует только `index.html`, `menu.html`, `css`, `js`, `assets`, `data`.
Папка `admin/` на Pages не попадает. `admin/config.php` и копии из `data/_backups/`
в git не попадают (`.gitignore`).
